A1. SESSION 1 - Trusting and shaping the data (pandas)
---------------------------------------------------------------------

A1.1 Cross-check the two label files.
  metadata.csv (per image) and training_gt.csv (per lesion) describe
  the same lesions. Before trusting them, verify IN CODE (with asserts
  and a printed summary of the violations, if any):
    (a) the set of lesion_id is identical in both files
    (b) every lesion has exactly ONE positive class in the one-hot gt
    (c) does each of the 11 classes map to exactly ONE diagnosis_1
        value? Build the table class -> diagnosis_1 with lesion counts
        and report every class that does NOT (with the counts)
    (d) each diagnosis_3 value belongs to exactly one diagnosis_2
        value, and each diagnosis_2 to exactly one diagnosis_1
    (e) the two images of a lesion have identical age, sex, site and
        diagnosis fields
  Then answer (4-5 sentences): what did you find in (c), and what does
  it imply for the label strategy of the project (could you derive
  diagnosis_1 from an 11-class prediction)? Which of these checks would
  you repeat on any new medical dataset before training, and which
  failure would be the most dangerous?

A1.2 Ask the data five questions.
  Answer each with a few lines of pandas (boolean masks, query,
  groupby) and print a single clear result:
    1. How many BCC lesions are in patients aged 70 or more on the
       head/neck?
    2. Which of the 11 classes has the highest percentage of images
       with image_manipulation == "altered", and what is that percentage?
    3. Youngest and oldest patient with a melanoma (MEL), and the gap.
    4. Is a missing anatom_site_general informative? Compare the class
       distribution of lesions WITH and WITHOUT a recorded site: which
       class changes the most (in percentage points)?
    5. How does the percentage of Malignant lesions change with
       diagnosis_confirm_type (e.g. histopathology vs. the other
       confirmation types)? What does that tell you about how the
       dataset was built and about which lesions get into it?

A1.3 Build a lesion-level table.

A3. SESSION 3 - Splits, imbalance, leakage, augmentation, datasets
---------------------------------------------------------------------

A3.1 Measure the leak (do not only count it).
  Counting leaked lesions is not enough: measure what a leak does to a
  metric. Train a scikit-learn RandomForestClassifier
  (min_samples_leaf=1, so it can memorise) on METADATA ONLY (age, sex,
  anatom_site_general, image_type; use a Pipeline so that any
  imputation/encoding is fitted on train only) to predict diagnosis_1.
  Evaluate balanced accuracy on the test part of
    (a) a naive image-level split (stratified on diagnosis_1)
    (b) a grouped split by lesion_id (StratifiedGroupKFold)
  Repeat with 5 seeds and report mean +- std for both.
    (c) Then compute the POTENTIAL of the leak with a "sibling oracle":
        predict each test image with the label of the lesion's OTHER
        image if that image is in train (otherwise the majority class of
        train). Report its balanced accuracy and the % of test images
        whose sibling is in train, for both splits.
    (d) Conclude in 4-5 sentences. Did the leak inflate the random
        forest's metric? If not, why not (what do the two images of a
        lesion share, and how strong is that information)? What does the
        oracle tell you about a model that CAN recognise a lesion (e.g. a
        CNN looking at the two views or at near-duplicate photos)? Why is
        "I did not measure any inflation" not a valid reason to skip the
        grouped split?

A3.2 A reusable three-way split.
  Write split_lesions(lesions, val_size, test_size, seed) that uses
  StratifiedGroupKFold at LESION level (using your table from A1.3)
  and returns three lists of lesion_id. Then write a property test that
  runs it with 10 different seeds and checks:
    - no overlap between any pair of splits
    - split sizes within +-1 percentage point of the requested sizes
    - same seed -> identical output (reproducibility)
  Report, over the 10 seeds, in how many cases each rare class
  (MAL_OTH, DF, INF, VASC, BEN_OTH) is present in val AND in test.
  What does that tell you about evaluating the rarest class?

A3.3 Why StratifiedGroupKFold?
  Compare three 5-fold strategies on the lesion table:
    (i)   GroupKFold             (groups, no stratification)
    (ii)  StratifiedKFold        (stratification, no groups; run on the
                                  IMAGE table)
    (iii) StratifiedGroupKFold   (both)
  For each report: number of leaked lesions across folds, the largest
  spread (max - min across the 5 folds, in percentage points) of any
  class proportion in the validation folds, and the number of folds
  in which MAL_OTH is absent from the validation fold. Present a table
  and conclude in 3 lines which strategy you would use and why.

A3.4 Metrics and the cost of errors.
  Using your test split (lesion level, diagnosis_1 with 3 classes):
    (a) evaluate three dummy predictors (always-Malignant,
        stratified-random, uniform-random), using sklearn.dummy.DummyClassifier,
        with accuracy, balanced accuracy and macro-F1, and show the confusion
        matrix of the stratified-random one
    (b) define an explicit cost matrix (rows = truth, columns =
        prediction; e.g. missing a Malignant costs 50, unnecessary
        work-up of a Benign costs 1, Indeterminate errors cost 5, any
        correct prediction 0) and compute the expected cost per lesion
        of the three dummies AND of always-Benign
    (c) which constant prediction is optimal under your costs, and does
        the ranking by accuracy agree with the ranking by cost?

A3.5 Is this augmentation label-safe? A quantitative audit.
    (a) Colour safety: measure the difference between Benign and
        Malignant in the mean HSV hue (degrees, use a circular mean)
        and mean brightness (V) of lesion pixels over 100 images per
        group. Compare with the change induced by ColorJitter hue in
        {0.02, 0.05, 0.1, 0.5} (hue*360 degrees) and brightness in
        {0.1, 0.3, 0.6}. Which parameters change colour MORE than the
        class gap itself?
    (b) In 4-5 sentences: which augmentations are safe, which are
        risky, and who must approve them?

A3.6 A lesion-level Dataset.
  Write LesionDataset(lesion_table, img_dir, label_col, transform,
  views=("derm", "clinical")) subclassing torch.utils.data.Dataset. Each
  item is ONE lesion and returns a dict with one tensor per requested
  view, the integer label and the lesion_id. Requirements: clear error
  if an image is missing; the transform is applied independently to each
  view; works with DataLoader(batch_size=8).
    (a) test: one batch has shapes (8, 3, H, W) per view, and the
        lesion_ids returned match the label table
    (b) iterate one epoch over 800 lesions and check the class counts
        seen equal the class counts of the subset
    (c) write aggregate_predictions(image_probs, image_table) that turns
        image-level class probabilities into ONE prediction per lesion
        (average of the two views) and test it with synthetic
        probabilities
    (d) in 3 sentences: what is the correct unit of evaluation for this
        project, and what goes wrong if you evaluate per image?
